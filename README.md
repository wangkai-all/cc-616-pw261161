# 渡口排班试算台

用本地造的数据跑通「原发班回放 → 停航/集中到达试算 → 等待分布核对」的完整流程。
只使用 Node.js 内置模块，无第三方依赖。

## 启动

```bash
node server.js            # 默认 http://127.0.0.1:3000
PORT=8080 node server.js  # 指定端口，仍只绑定 127.0.0.1
```

浏览器打开 `http://127.0.0.1:<PORT>/`，页面上可以：

- **回放原发班方案**：严格按原始到达日志与原始每班限额重放，不经过任何调度试算，随时退回原输入版
- **试算停航和集中到达**：在到达日志之外叠加「一艘停运」与「一批集中到达」，按已排队人数和调度条件排班
- **查看等待分布**：等待时间直方图；做「比较两种发船」时同时给出定点发船与等满发船的尾部对比
- **比较两种发船**：同一批到达、同一停航情景下，定点发船 vs 等满发船的未清队列、空座、等待取舍

所有业务结果都渲染在带有 `data-evidence-result="ferry-dispatch-result"` 的区块内；
该元素上的 `data-view-kind` / `data-mode` / `data-denominator` / `data-arrival-count` /
`data-departures` / `data-unboarded` 会随每次操作变化，便于核对操作前后的内容。

## 测试

```bash
node --test
```

覆盖引擎（原发班回放、间隔只换班次不换分母、停航与集中到达、等满/定点取舍、
空场景、非法参数）与服务端（接口、错误码、静态资源、PORT 解析、目录穿越），
以及一段在最小 DOM stub 上运行的前端渲染逻辑。

## 结构

```
server.js              HTTP 服务（内置 http/fs/path），读取 PORT，绑定 127.0.0.1
lib/engine.js          纯函数引擎：回放、试算、策略对比、参数校验
data/dataset.js        本地种子数据：到达日志与每班限额是两份独立输入
public/                页面（原生 ES module，无构建步骤）
test/                  node --test 用例
```

## 口径说明

- **到达日志**与**每班可登船限额**是两份独立输入，服务端从不合并或改写。
- **需求分母** `demandTotal` 只由到达日志和统计终点决定；改发船间隔、改调度规则、
  加停航都不改变它（对应结果里带指纹）。只有加「集中到达」才会让分母变大。
- **未上船者**按「到达至统计终点」计时（截尾等待），并入平均/最长等待和直方图，
  因此不同方案可以在同一分母下比较。
- **等满发船**：排队人数达到开船人数即发；若最久等待到点仍未满，则提前开船
  （记为「未满·等待到点」，代价是空座）。
- **定点发船**：按间隔到点发，有排队才发；若到点无可用渡船（两船都在往返或停运），
  该班取消并记一条调度事件。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 服务与数据状态 |
| GET | `/api/dataset` | 原始到达日志、每班限额、情景种子 |
| GET | `/api/replay` | 原发班方案回放结果 + 原输入快照 |
| POST | `/api/trial` | `{ config }` 或平铺 config；返回试算结果 + 与原发班的对比 |
| POST | `/api/compare` | 同一情景下定点发船 vs 等满发船 |

参数非法返回 `400` 及 `{ ok:false, error:{ code, message, field } }`；
请求体超过 64KB 返回 `413`；方法不匹配返回 `405` 并带 `Allow`。
